# 判定数（MAX / 300 / 200 …）是怎么获取的

> 对应插件：`astrbot_plugin_osu_scorecard`
> 相关文件：`card.py`（映射与 `judgements()`）、`osu_api.py`（官服）、`sb_api.py`（私服）

---

## 核心：同一个游戏，两套命名，而且行话还在变

| 卡上的槽位 | stable 叫法 | lazer 叫法 | 官服 API 字段 | 私服 API 字段 |
|---|---|---|---|---|
| `count_max` | MAX (320) | PERFECT | `statistics.perfect` | `ngeki` |
| `count_300` | 300 | GREAT | `statistics.great` | `n300` |
| `count_200` | 200 | GOOD | `statistics.good` | `nkatu` |
| `count_100` | 100 | OK | `statistics.ok` | `n100` |
| `count_50` | 50 | MEH | `statistics.meh` | `n50` |
| `count_miss` | MISS | MISS | `statistics.miss` | `nmiss` |

- **stable 时代**：`MAX / 300 / 200 / 100 / 50 / MISS`
- **lazer 时代**：改叫 `PERFECT / GREAT / GOOD / OK / MEH / MISS`
- **官服 API 用 lazer 名**；**私服 API 用 stable 名**（`ngeki` 这种前缀是 osu! 老 v1 API 的风格）

卡片槽位用的是 stable 名，所以两边进来都要做一层映射。

---

## 坑 1：值为 0 的键，官服压根不返回

实测 `/scores/6645548845` 返回：

```json
"statistics": { "perfect": 2295, "great": 617, "good": 10, "ignore_hit": 888 }
```

**注意这里没有 `ok`、没有 `meh`、没有 `miss`** —— 因为它们都是 0，`statistics` 里就**不存在这个键**。

> **所以取值必须用 `.get(k, 0)`，不能用 `[k]`。**
> 用下标会直接 `KeyError`，把整张卡搞挂。

---

## 坑 2：`ignore_hit` 不是判定，必须排除

`ignore_hit` 是 lazer 的额外统计（那局是 888）。如果把它当判定算进去，**总数就对不上了**：

```
2295 + 617 + 10        = 2922   ✅ 正好等于玩家的最大连击（满连）
2295 + 617 + 10 + 888  = 3810   ❌ 多了 888
```

---

## 坑 3：`judgements()` 返回的是模板图层名，不是 API 名

插件里 `judgements()` 返回的是 **`count_max` / `count_300`**，
而**不是** API 的 `perfect` / `great`。

这个差异导致过一个**静默 bug**：

- `pp_max` 的计算函数读的是 `perfect` / `great` → 拿不到 → 返回 `None`
- 结果**卡上那一格一直是 `--`**
- 而自检**一直是绿的** —— 因为它喂的是原始 API 形状，不是真实路径的形状

这是这个插件历史上最典型的一类 bug：**测试喂的形状和真实调用路径不一致**。
同样的错误在这个项目里出现过至少三次（`total_pp`、`judgements` 的键名、私服两个接口的形状）。

---

## 一个免费的交叉验证手段

**判定数的总和是个很好的自检基准：**

- **满连时**：`六判定总和 == 玩家的 max_combo`
- 我们用这个验证过 `6645548845` 是满连
- 也是用这个**证明了理论最大连击是 2922，而不是 API 说的 3243**

> 如果你看到卡片上**判定总数和 COMBO 差很多、但 MISS 是 0**，
> 那多半是哪个判定没被正确读到，而不是玩家真的漏了。

---

## 附：`maximum_statistics` 是另一个字段

官服成绩里还有 `maximum_statistics`，它记录的是**理论最大判定分布**，
可以用来推导满连，**零网络请求**。

stable 成绩例：`{ "perfect": 2432, "ignore_hit": 1248 }`
lazer 成绩例：`{ "perfect": 1808, "legacy_combo_increase": 955 }`（`1808 + 955 = 2763` = API 的 `max_combo`）

**目前没有接进插件** —— 要在不知道成绩类型的前提下安全使用，需要额外的判别逻辑。
如果想省掉下载 `.osu` 那一步，这是最值得做的优化。
