# 快速导出试验（2026-10-15）

## 当前实现

后续修正：回放自动使用 DT / NC / HT 及 lazer 自定义倍速；读取 lazer 扩展 Mod 与完整统计。网页仍在结尾进入成绩卡，导出视频结束于最后音符后的 2 秒音乐，不包含成绩卡或转场。

- WebCodecs 优先请求受支持的 H.264 硬件编码配置，不支持时保留浏览器默认选择。
- 导出时游戏和 HUD 直接使用输出尺寸的像素画布；逻辑坐标仍为 1920×1080，所以皮肤和编辑布局的位置不变。结束或失败后恢复预览画布。
- 默认手动导出 1280×720、60 FPS、3 Mbps，可切回 1920×1080、60 FPS、6 Mbps；后台任务仍按请求的尺寸和码率输出。
- 谱面按时间和长条结束时间建立索引；用二分与区块跳过不可见音符。判定累计、连击、CPS、UR、按键记录采用预计算／时间索引，支持向前与向后拖动。
- 编码队列通过 dequeue 事件等待；界面定期通过 scheduler.yield / MessageChannel 让出执行时间。音频编码同样避免逐块定时器等待。
- 导出控制栏显示实际生成帧速；该数值与视频的 60 FPS 播放帧率不同。

## 实测

同一台 Windows 设备，同一份 F6A8AF 的 DiSANiMATE 回放、owc 皮肤，取谱面 250–265 秒区间。两版都输出 1280×720、60 FPS、6 Mbps、900 帧；测速排除素材加载与音频，包含绘制、画布合成、视频编码与编码队列排空。

| 版本 | 第一轮 | 复测 |
|---|---:|---:|
| 优化前 | 3.685 秒 / 244.2 帧每秒 | 3.634 秒 / 247.6 帧每秒 |
| 试验版 | 2.863 秒 / 314.4 帧每秒 | 2.787 秒 / 322.9 帧每秒 |

复测生成速度提高约 30%，耗时减少约 23%。浏览器报告图形设备为 NVIDIA RTX 5060 Laptop；编码配置接受 prefer-hardware。WebCodecs 不直接报告最终编码器名称，因此不把偏好设置当作实际编码器的独立证明。

这些是该回放区间的实测，整曲、其他皮肤或其他设备仍可能不同。原始结果保存在 `scratch/export-fast-20261015/*.json` 与 MP4 中。

## 验证

- `node renderer/tools/test_frame_index.mjs`：时间边界、长条保留、判定／连击／CPS／UR、反向拖动、编码器回退、画布恢复。
- `node renderer/tools/benchmark_export.cjs baseline-final <回放.osr>` 与 `current-final`：同输入测速；编码后用 FFmpeg 实际解码帧再比较。不能仅凭 video.seeked 后立即 drawImage 的空帧判定图像一致。
- 实际采样的判定、连击、CPS、UR 与旧版完全一致；实际解码帧 RGB 平均绝对差约 1.21 / 255，95% 的分量差不超过 3。未发现布局偏移。
- `test_skin_effects.cjs --all`：owc、R Skin、boj、Cho 与新导入皮肤的音符／光柱／闪光坐标。
- `test_scene_flow_browser.cjs`：短前奏、开场动画、2 秒结尾音乐、成绩卡淡入、AAC 音轨、MP4 时长与最后一帧；720p 导出后恢复 1080p 预览。
