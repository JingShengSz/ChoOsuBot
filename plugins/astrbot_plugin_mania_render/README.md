# astrbot_plugin_mania_render

> **行为变更**：本插件**不再自动检测消息里的 osu! 成绩链接**。
>
> 原因：`astrbot_plugin_osu_scorecard` 也会抓同一条链接，两个插件同时响应会把一次操作
> 渲染两遍。现在成绩链接归 `astrbot_plugin_osu_scorecard`（出成绩卡），本插件只负责
> 显式指令 `om <谱面ID>` / `om` 回复 `.osr`，以及 LLM 工具 `render_mania_video`。
>
> 想恢复自动检测：`main.py.bak_before_autoscore_removal`，或按 `main.py` 里的注释重建
> （被删的是 `auto_score()` 处理函数和 `auto_score_enabled` 属性，`_score_replay()` 等
> 依赖都还在，恢复时不用重写网络层）。


把 osu!mania 谱面 / `.osr` 回放渲染成 **MP4 视频**并发到聊天里。

插件自身不做渲染，它调用独立的 [`mania-render`](../README.md) HTTP 服务：提交任务 →
轮询进度 → 下载 MP4 → 交给平台适配器发送。

默认输出 **1920×1080 / 60fps / H.264 MP4**（QQ 可以直接当视频播放，不是 webm）。

开始时只回一句「渲染视频需要几分钟，请稍等」，**渲染中途不再刷进度**（进度写进 AstrBot
日志，供排查用），完成后直接把视频发出来。

---

## 0. 两条指令，先记住这个

| 用法 | 说明 |
|---|---|
| **`om <谱面ID>`** | 例：`om 2467450` |
| **`om`（回复一条带 `.osr` 的消息）** | 机器人会去读**被回复那条消息**里的 `.osr`，用回放渲染 |

```
用户：om 2467450
用户：[发了一个 .osr 文件]
用户：om                      ← 回复上面那条 .osr 消息
```

两种都可以再加选项：

```
om 2467450 -s R Skin -d 30 -v 25
om 2467450 --from 60 --to 75
```

## 1. 给 LLM 的调用说明

> 这一节就是给模型看的。人类使用者可以跳到第 2 节。

### 1.1 你能用的工具

**工具名：`render_mania_video`** —— 把谱面或回放渲染成视频发给用户。

| 参数 | 类型 | 说明 |
|---|---|---|
| `bid` | string | 谱面 ID，纯数字，取自 osu! 谱面链接 `/b/` 后面那串（`https://osu.ppy.sh/beatmaps/2467450` → `2467450`）。**用户回复的是 `.osr` 时留空。** |
| `skin` | string | 皮肤名。**必须**来自 `om皮肤` 列出的列表，支持子串匹配。留空 = 默认皮肤。 |
| `bg_dim` | string | 背景暗度，`0`–`100` 的百分比（也接受 `0`–`1` 的小数）。`0` = 背景原样，`100` = 全黑。默认 `60`。 |
| `scroll_speed` | string | 音符下落速度，`1`–`40`。数字越大下落越快。默认 `30`。 |
| `resolution` | string | `1080` 或 `720`。默认 `1080`。**除非用户明确要 720，否则不要传。** |
| `fps` | string | 帧率，`1`–`120`。默认 `60`。 |
| `start_seconds` | string | 只渲染片段时的起始秒；留空表示从头开始。 |
| `end_seconds` | string | 片段结束秒，必须大于起始秒，**片段最长 120 秒**。 |

**注意**：所有参数都是字符串类型（框架只解析 docstring，不读函数注解）。
用户没有明确说的参数**不要自己填**，留空就会用默认值。

### 1.2 用户怎么说 → 你怎么调

| 用户的话 | 你应该传 |
|---|---|
| “渲染一下 2467450” | `bid="2467450"`，其余留空 |
| **“om”/“渲染这个”并回复了一条带 .osr 的消息** | **`bid` 留空** —— 插件会自动读被回复消息里的 `.osr`，你不用做任何事 |
| “用 R Skin 皮肤渲染 2467450” | `bid="2467450", skin="R Skin"` |
| “背景暗一点 / 暗度 30” | `bg_dim="30"`（数值越大越黑） |
| “背景别那么暗 / 亮一点” | `bg_dim="20"` 或更小 |
| “音符掉太快了 / 慢一点” | `scroll_speed="20"`（默认 30，越小越慢） |
| “音符太慢了 / 快一点” | `scroll_speed="38"` |
| “要清晰的” | 什么都不用传，默认就是 1080p |
| “720p 就够了 / 文件太大了” | `resolution="720"` |
| “只要 60 秒到 75 秒那段” | `start_seconds="60", end_seconds="75"` |
| 用户发了 `.osr` 又给了 ID | 两个都传，回放优先，ID 作为匹配不上时的兜底 |

### 1.3 你要遵守的规则

1. **调用前确认有谱面 ID，或者用户回复/发送了 `.osr`。** 两者都没有时，直接告诉用户
   「发一个谱面 ID，或者回复一条带 .osr 的消息」，**不要瞎猜 ID**。
2. **皮肤名不确定就先查**。不要编造皮肤名——编错会被拒绝并返回可用列表。可用值来自
   `om皮肤`。
3. **渲染很慢，别重复提交**。一首 3 分钟的图在 2 核服务器上要几分钟；同一个请求
   不要连着调两次。
4. **返回的是状态文本**，视频由插件自己发出去。你只需要把状态转述给用户
   （例如「视频已发送」或具体错误）。**不要**再说「我生成好了，请查收」之类没有依据的话。
5. **超长谱面优先建议片段**。用户只想看某个高光时，用 `start_seconds`/`end_seconds`
   比整首快得多。
6. 渲染失败时把返回的错误**原样转述**（常见：谱面 ID 不存在、非 mania 谱面、
   皮肤无对应键数配置、任务超时）。

### 1.4 人类用户可用的命令

| 命令 | 作用 |
|---|---|
| **`om <谱面ID> [选项]`** | 渲染并发视频（别名 `mania` / `渲染` / `osu`） |
| **`om`（回复带 `.osr` 的消息）** | 用被回复消息里的回放渲染 |
| `om皮肤` | 列出可用皮肤（别名 `mania皮肤` / `皮肤列表`） |
| `om参数` | 显示当前默认参数和服务地址 |

**选项**（三种写法等价：`-s R Skin`、`skin=R Skin`、`皮肤 R Skin`）：

| 选项 | 取值 | 说明 |
|---|---|---|
| `-s` / `skin` / `皮肤` | 皮肤名 | 支持子串，如 `R Skin`、`boj`、`Cho`。**名字里可以带空格**：`-s R Skin` 会把两个词一起当作皮肤名 |
| `-v` / `scroll` / `速度` / `滚动` | 1–40 | 滚动速度，默认 30 |
| `-d` / `dim` / `暗度` / `背景` | 0–100 | 背景暗度，默认 60 |
| `-r` / `res` / `分辨率` | `1080` / `720` | 分辨率，默认 1080 |
| `-f` / `fps` / `帧率` | 1–120 | 帧率，默认 60 |
| `--from` / `--to` / `起` / `止` | 秒 | 片段范围，最长 120 秒 |

例：

```
om 2467450
om 2467450 -s R Skin -d 30 -v 25
om 2467450 分辨率 1080 帧率 30
om 2467450 -r 720
om 2467450 --from 60 --to 75
```

## 2. 回放怎么给

| 方式 | 怎么做 |
|---|---|
| **回复一条带 `.osr` 的消息，发 `om`** | 推荐。插件用 `get_msg` 读出被回复消息里的文件段。 |
| 把 `.osr` 和 `om` 发在同一条消息里 | 也支持，会优先用本条消息里的文件。 |
| `.osr` + 谱面 ID | 回放优先；回放的 MD5 在线查不到谱面时，用你给的 ID 兜底。 |

> 合并转发（`Nodes`）里的 `.osr` **不支持**，请直接回复那条文件消息。

## 3. 安装

1. 把 `astrbot_plugin_mania_render/` 整个目录放进 `AstrBot/data/plugins/`。
2. 在 WebUI 插件页点「**重载插件**」（新增插件目录后必须重载一次）。
3. 在插件配置里确认 **mania-render 服务地址**（同机部署填 `http://127.0.0.1:8760`）。
4. 依赖只有 `aiohttp`，AstrBot 自带。

## 4. 先跑起渲染服务

插件不渲染，所以必须有一个 mania-render 服务在跑：

```bash
cd osu-mania-render
export MANIA_SKINS_DIR=/opt/mania/skins          # 可选，默认 <项目>/skins
python -m mania_render --web --host 127.0.0.1 --port 8760
```

启动时会打印实际使用的皮肤目录、注册数量与默认皮肤。用
`curl http://127.0.0.1:8760/api/skins` 可以确认插件能看到哪些皮肤。

> **2 核 2 GB 的机器上不要并发渲染**：一个任务就占掉大半内存。本插件用
> `asyncio.Lock` 保证同一时间只提交一个任务，后来的排队等待。

## 5. 视频投递方式

| 模式 | 适用 | 说明 |
|---|---|---|
| `file`（默认） | 协议端（LLBot / NapCat / Lagrange）和本插件**在同一台机器** | 直接把文件路径交给适配器，最快，不占带宽 |
| `url` | 协议端在**另一台机器** | 发送 `http://<服务地址>/api/download/<任务号>`，由协议端下载 |

## 6. 缓存与清理

- 下载下来的 MP4 存在 `data/plugin_data/astrbot_plugin_mania_render/`，
  插件只保留最新 **5** 个，更旧的在下次下载时删除。
- 服务端自己的 `cache/renders/` 不归插件管，长期运行要自己加清理。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 指令没反应 | 新装的插件要在 WebUI 点一次「重载插件」。 |
| **WebUI 里根本看不到这个插件，失败列表里也没有** | `metadata.yaml` 的 `name` / `desc` / `version` / `author` 必须都是**非空字符串**。写成 `author: ""` 会被 AstrBot 的元数据校验拒绝；而且首次导入时该异常只降级成 warning，插件以 `name=None` 加载后被 `is_ghost_plugin()` 判定为幽灵插件，从插件列表里静默消失。改好字段再「重载插件」即可。具体报错去 `GET /api/v1/logs/history` 里搜 `Failed to load plugin`。 |
| “提交渲染任务失败” | 渲染服务没起来，或配置里的地址不对。`curl <地址>/api/skins` 试一下。 |
| “没有叫「xxx」的皮肤” | 皮肤名写错了。先 `om皮肤` 看列表；服务端加皮肤要重启服务。 |
| “皮肤无 4K [Mania] 配置” | 该皮肤没写这个键数的段落，换一个皮肤。 |
| “非 mania 谱面” | 给的是 std/taiko/catch 的 ID，不是 mania。 |
| 回复 .osr 后说拿不到文件 | 协议端不支持 `get_msg`，或该文件是转发消息里的。改成直接发送 `.osr`。 |
| 渲染超时 | 默认 1800 秒。长图在低配机器上很慢，建议 `--from/--to` 出片段。 |
| 视频发不出去 | 多半是投递方式不对：协议端不同机时改 `url`。 |

## 8. 开发说明

- 入口 `main.py`，插件类 `ManiaRenderPlugin(Star)`。
- 命令：`om` / `om皮肤` / `om参数`；LLM 工具：`render_mania_video`。
- 仓库根目录下的自测脚本（不需要装 AstrBot 就能跑前两个）：
  - `tools/plugin_arg_selftest.py` —— 参数解析
  - `tools/plugin_package_check.py` —— 按开发手册逐条检查包结构；`metadata.yaml`
    直接交给 **AstrBot 自己的** `_PluginUpdater.validate_plugin_metadata()` 判定
    （找不到 AstrBot 时退回本地镜像规则），所以 `author: ""` 这类会让插件静默消失的
    字段一定会在打包前被拦下来
  - `tools/plugin_runtime_check.py` —— **用 AstrBot 自己的解释器**加载插件、检查注册表、
    `--live` 还会真的跑一次渲染
- 网络请求全部走 `aiohttp`，没有 `requests`。
- 持久化只写 `data/plugin_data/<插件名>/`，不写插件目录。
